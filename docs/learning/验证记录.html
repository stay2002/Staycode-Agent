2. 静态对比方法

  1. 枚举原目录中的 .py 文件，排除 __pycache__。
  2. 对相对路径作 mewcode → staycode 映射，定位目标文件。
  3. 以 UTF-8（允许 BOM）读取 Python 源文件，将文本中的 mewcode、staycode 不分大小写替换为统一占位词 BRAND。
  4. 使用 ast.parse() 解析，再以 ast.dump(..., include_attributes=False) 比较。该比较忽略行列号和注释，保留语法结构以及归一化后的字符串常量、文档字符串。
  5. pyproject.toml 使用 tomllib 解析、排序序列化后比较；uv.lock 对品牌归一化后的文本作比较。

本轮执行采用以下保护：

  • 新建系统临时目录，切换进程 cwd 到该目录；将该子进程的 HOME、USERPROFILE 指向临时 home。
  • 保留产品和测试文件在原路径，只为导入向 sys.path 加入项目路径。
  • Python 使用 -X utf8 -B；pytest 使用 -p no:cacheprovider，避免在项目写入字节码和 pytest 缓存。
  • 禁止自动加载无关 pytest 插件，仅显式加载 pytest_asyncio.plugin。
  • 五文件执行进程移除 OPENAI_API_KEY、ANTHROPIC_API_KEY；收集进程还移除 STAYCODE_TEST_API_KEY。这些修改只存在于短命验证进程中，不修改用户永久环境变量。
  • 通过 sys.addaudithook() 阻止全部 subprocess.Popen。执行阶段阻止外部 socket.connect，只保留 127.0.0.1、::1 回环连接，以兼容 Windows 事件循环内部使用。收集阶段禁止全部子进程和 socket 连接。
  • test_toolresult_wiring.py 自身使用 tmp_path 并切换到它；根 fixture 还把 Path.home() 指向测试临时 home。额外的进程隔离避免依赖 fixture 注释所声称的隔离范围。

6. 配置只读原则与额外探针

本轮未读取或输出实际 config.yaml、config.local.yaml、config.yaml.example 中的配置值或密钥，也没有执行默认 load_config()。研究依据为 staycode/config.py、staycode/validator.py 的实现。

额外配置探针只在内存中构造虚构 ProviderConfig、AppConfig，使用 https://example.invalid/v1 与演示模型名，没有建立客户端或发送网络请求。探针复核了以下现有行为：

  • 后层 providers 整表替换；permission_mode: default 不能覆盖前层非 default。
  • 后层缺省 enable_fork: true 会重新打开前层的 false。
  • verification、coordinator 与 sandbox 布尔字段不能通过后层 false 关闭前层 true。
  • 空 teammate_mode 不能清除前层值；后层 worktree 设置没有被合并。
  • 缺少 providers 的单层配置会被校验器拒绝。

这些是实现事实，不是本轮修复内容。合并规则详见 staycode/config.py 的 _merge_config()，每层校验见 staycode/validator.py 的 validate_config_structure()。

9. 教材配套实验与阅读版核验

教材主任务另运行了 docs/learning/labs/trace_agent_loop.py：真实 Agent.run() 使用 ScriptedClient 和纯函数 AddNumbers，完成两次模型响应、一次工具调用，工具 ID 与结果配对、最终消息和循环结束断言通过，退出码 0。此处没有真实 LLM 请求，也没有将实验工具加入产品默认注册表。首次运行发现实验序列化调用传入了 ConversationManager 而非消息列表，修正为 get_messages() 后复跑通过。

build_reader.py 从同一 Markdown 生成 HTML、源码导航与符号索引，并检查 18 章数量、目录锚点、本地链接、行号范围和代码围栏。额外检查 HTML 实际链接，修复了中文路径经过 Markdown 渲染后再次编码的问题；最终检查结果见 evidence/document-check.json 与 evidence/html-links.json。

阅读版使用本地内联 CSS、JavaScript 和 SVG，没有外部脚本或字体依赖。Playwright 的 file 协议访问被工具限制，因此通过仅绑定 127.0.0.1 的临时静态服务器核验 HTML；这不是启动 StayCode Remote，也没有启动模型服务。检查范围包括 1440×1000 桌面和 390×844 手机宽度、18 个进度复选框、20 个导航项、无重复 ID、无缺失锚点、关键词筛选、章节跳转、进度写入与清除，以及无整页横向溢出。截图保存在 evidence/reader-*.png。

浏览器检查不代表所有浏览器的 file-origin 存储、剪贴板和打印行为均已验证。源码链接保留本机路径；若移动项目，重新运行构建脚本并调整教材中的根路径。以上检查未扩展到产品 TUI、Remote、真实模型或完整测试套件。
